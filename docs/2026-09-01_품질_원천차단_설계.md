# 보고서 품질 4대 결함 클래스 원천 차단 — 설계 확정본 (2026-09-01)

철강 심층 정독(2026-08-29, 6.0/10)과 출처 일원화 전수 판정(26쌍)에서 확정된
결함 클래스 4종의 예방·차단 설계. 두 차례 설계 검토(2026-09-01)의 수정을 반영한
최종본이며, 층 구조와 구현 순서의 단일 참조 문서다.

## 층 구조 (지우는 주체와 시점)

| 층 | 시점 | 주체 | 하는 일 |
|---|---|---|---|
| 층1 예방 | 계획·검색 | 결정 코드+브리프 LLM | 같은 재료가 두 절에 안 가게 (소유권·builds_on·질의 분화·청크 예산) |
| 층2 결정층 | 절 저장 직전 | **코드만** | 마커 3상태 교정 + 절 내 중복 소거 (`sections/citation_repair`) |
| 층3 조립 압축 | assemble | 코드 검출 + LLM 압축 | 절 간 중복 문단 → "(X.Y절 참조)" (실패 시 원문 유지) |
| 층4 감사 | 완성 후 | 코드 검출 → 사람 | 경고만. **층2·3이 지우고 고친 것도 여기서 노출**(감사 닫힘) |

원칙: 되돌리기 어려운 행위(삭제)는 결정적 코드만, LLM은 원문 유지 폴백이 있는
재작성까지. 근거 = 같은 본문·temp 0에서 LLM 판정 44→54건 요동 실측.
층1이 강해져도 층2·3은 끄지 않는다 — 층1은 계획 시점의 예측이고 예측은 틀린다.
**층2·3 검출 건수가 층1 효과의 가장 깨끗한 지표다**(소유권을 켜면 줄어야 정상).

## 클래스별 확정 설계

### ① 절 간 재탕 (철강 4.3의 79%·5.1의 절반·6.2의 3/4)

근본 원인 실측: 코퍼스 편중(DX 설문 1개가 641/1,417청크=45%) + 소유권 그물 좁음
(상한 3~8토픽이 반복 소재 못 덮음, owns 6중 append 버그) + 결론 장이 앞 절
최종본을 못 봄(병렬 작성).

- **1-B 데이터 기반 소유권** (미구현, ~1일): 리허설 검색 결과로 자료×절 행렬을
  만들어 3개 절 이상 상위 등장 자료를 결정적으로 강제 배정. 지배 문서(청크 25%+)
  무조건 배정. owns dedup 동봉.
- **1-C 결론 장 재료화** (미구현, 3~4일): 시사점·SWOT 절은 검색 팩 대신 앞 절
  최종본을 재료로. **필수 제약 두 개** —
  - 마커 상속: 앞 절을 넘길 때 문장↔cited_chunk_ids 매핑을 동봉해 받아 쓴 문장이
    원 청크 마커를 물려받는다. "(X.Y절)" 참조 표기는 독자용이지 근거 추적이 아니다
    (cited가 비면 uncited 검사·근거 배지·renumber가 결론 장에서 통째 무력화).
  - 새 수치 금지는 프롬프트가 아니라 **사실 대장 대조 결정 게이트**(저장 전 차단).
    요약 체인 전달 실험에서 무근거 +39%였던 계열이라 프롬프트로는 못 막는다.
  - 표적 근거: 계층 작성 실험에서 유일한 수혜가 종합 절이었다.
- **1-A 청크 전역 예산** (재설계 후 후순위, 자료 점유율 아님): 한 청크가 주 근거로
  쓰이는 절 수 상한 2~3. 자료 단위 쿼터는 효과 상한 실증(자료 다양한 2장에서도
  20~22문장 중복 — 편중은 증폭기지 원인이 아님)으로 강등.

### ② 절 간 수치 모순 (3.1↔3.2)

**배포 완료 스택**: 사실 대장 주입·조인 + PM 입력 절단 해제(24k→120k) + 상충 병기
작성 규칙. 남은 배선 1건: 겹침 카드(outline_overlaps) 승인 → topic_ownership 자동
반영(~반나절). 철강은 대장 이전 런이라 효과 미실측 — 다음 런이 검증.

### ③ 절 내부 중복 (1.2 같은 문단 두 벌)

- **층2 절 내 소거** (구현 완료, `dedup_intra_section`): 0.8+ 복사 수준 뒤 문장을
  결정적 삭제. 가드 전부 결정적 —
  - **숫자 집합이 다르면 삭제 금지** (연도별 추이 문장 = 골격 같아도 정보)
  - 삭제는 뒤 등장(rfind)·줄 전체 일치일 때만 (문장 조각 금지)
  - 고아 하위 불릿·지시어 후속("이는…")이면 포기
  - 첫 중복 1건 항상 + 이후 15% 예산. **예산 소진은 성공이 아니라 경보** —
    budget_exhausted 플래그가 층4로 올라가 재처리 후보로 표시
- **3-A 파트별 청크 배타 배정** (미구현, ~1일): 파트 계획 산출에 청크를 배타
  배정해 같은 재료가 두 파트에 못 가게. **파트 계획 폴백(n_titles=0) 시 배타
  배정 off 명시**, 재료 없는 파트 라운드로빈 보충 금지(채우기 압력=무근거) —
  파트 수 축소로 대응.

### ④ 출처 오귀속 (같은 문장 절마다 출처 4벌)

- **층2 마커 3상태 교정** (구현 완료, `repair_citations`):
  - 교정: 인용 청크에 없는 수치가 팩의 **한 청크에 전부** 실재할 때만 그 청크로
  - 유지: 실재·양쪽 실재(26쌍 중 16쌍이 정당한 교차 인용이었다)·파생값·외국어 근거
  - **보류: 팩 어디에도 없음 — 마커 불변, 플래그만**(파생 아니면 환각 후보.
    억지 교정은 경고만 하던 종전보다 나쁘다)
  - 치환은 주장 단위 안 마커만(줄 단위는 표 이웃 셀을 덮은 실사고), 직접 인용
    [n]·다중 마커 문장은 판정 제외
  - **cited_chunk_ids 동시 재규약**(첫 등장 순서) — 안 하면 renumber에서 절 전체
    인용이 밀린다. 유령 번호가 있으면 절을 통째로 회피.
  - 수치 대조는 무근거 검출기와 같은 함수(gate.numeric_mentions/number_in_text/
    derived_numbers) — 교정과 검출의 눈금 일치.
- 완성 보고서의 사후 일원화는 같은 판정 로직의 스크립트(철강에서 5+6건 실증).

## 감사 계약 (층2는 조용히 틀릴 수 있다)

결정 코드의 체계적 오류는 매 런 똑같이·조용히 틀리고, 지워진 것은 안 보인다.
그래서 층2의 모든 행위가 기록으로 남는다:

- `RepairOutcome.audit()` → 절 meta `citation_repair` = {removed(쌍+유사도),
  fixed(마커 전/후), held(보류 수치), budget_exhausted}
- 층4 검증 카드 소견 3종: "자동 소거 N건(예시·유사도)", "마커 자동 교정 N건",
  "소거 예산 소진(재처리 후보)"
- 경로: 작성(생존 초안)·재작성(_apply_section_rewrite)·후보안 채택 전부 meta 전달
- 되돌리기: `write_citation_repair` / `write_intra_dedup` 설정 한 줄

## 검증 프로토콜

- 신규 런 지표 금지 — 실행 간 변동(±17~43%)에 묻힌다. **철강 코퍼스를 회귀
  코퍼스로 고정하고 동일 입력 재실행**으로 전후 비교.
- 임계 0.8은 철강 실측 기반 — 0.78~0.85 **경계 구간 표본**을 코퍼스별로 다시 보는
  절차를 남긴다(전역 상수 아님, 문체 의존).
- 가드레일 지표: **절 길이 분포** — 제거 방향 처방들이 보고서를 조용히 얇게
  만드는지 감시.
- 층1 효과 = 층2·3 검출 건수 감소로 측정.
